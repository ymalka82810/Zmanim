# חיבור האתר לגוגל (פעם אחת)

בעל האתר עושה את זה פעם אחת בלבד, ולא עבור כל גבאי. זה בחינם ולוקח כעשרים דקות. יש שני חלקים:

- **מזהה התחברות** (שלבים 1–5, חובה): מאפשר לגבאי ליצור גיליון בדרייב שלו מתוך הלוח.
- **שומר הסף** (שלב 0, רשות): סקריפט אחד בחשבון שלך שקורא את הלוחות וכותב רישומים, ורק לשבת פנויה. הוא משרת את כל בתי הכנסת.
  בלעדיו (`gateUrl` ריק) הגיליון משותף לעריכה לכל מי שיש לו את הקישור, המתפללים כותבים בו ישירות, ואין הגנה מפני מחיקת רישום של אחר.
  גיליונות שנוצרו לפני שהוספת את השומר נשארים פתוחים לעריכה. כדי להגן עליהם, הגבאי משנה בגיליון את השיתוף ל"מוגבל".

## 0. שומר הסף (Apps Script)
1. נכנסים ל-https://script.google.com עם חשבון הגוגל שלך ולוחצים **New project** (פרויקט חדש).
2. משנים את שם הפרויקט (למעלה, "Untitled project") ל-`שומר הסף – לוח קידושים`.
3. מוחקים את כל מה שכתוב בקובץ `Code.gs`, ומדביקים במקומו את התוכן של `kiddush/apps-script/Code.gs`. שומרים (Ctrl+S).
4. לוחצים **Deploy ← New deployment**. ליד Select type לוחצים על גלגל השיניים ובוחרים **Web app**.
   - **Execute as**: `Me`
   - **Who has access**: `Anyone`
5. לוחצים **Deploy ← Authorize access**, בוחרים את החשבון שלך.
   גוגל תציג "Google hasn't verified this app". זה תקין, כי זה הסקריפט שלך: לוחצים **Advanced ← Go to ... (unsafe) ← Allow**.
6. מעתיקים את **Web app URL** (נגמר ב-`/exec`).

החשבון שלך יקבל הרשאת עריכה לכל גיליון שגבאי יוצר, כי דרכו השומר כותב. כדאי שהגבאים יידעו את זה.
השומר עובד רק על גיליונות שנוצרו מתוך הלוח, גם אם יש לחשבון שלך גישה לגיליונות אחרים.

**עדכון הסקריפט בעתיד:** מדביקים את הקוד החדש, ואז **Deploy ← Manage deployments ← עיפרון ← Version: New version ← Deploy**.
כך הכתובת נשארת אותה כתובת.

## 1. פרויקט חדש
1. נכנסים ל-https://console.cloud.google.com עם חשבון הגוגל שלך.
2. למעלה, ליד הלוגו, לוחצים על בחירת הפרויקט ואז **New Project**.
3. שם: `Zmanim`. לוחצים **Create**, ומוודאים שהפרויקט החדש נבחר למעלה.

## 2. הפעלת הממשקים
1. בתפריט: **APIs & Services ← Library**.
2. מחפשים **Google Sheets API**, נכנסים ולוחצים **Enable**.
3. חוזרים ל-Library, מחפשים **Google Drive API** ולוחצים **Enable**.

## 3. מסך ההסכמה (מה שהגבאי רואה כשהוא מתחבר)
1. בתפריט: **APIs & Services ← OAuth consent screen**. אם מופיע **Get started**, לוחצים עליו.
2. **App name**: `לוח קידושים`. **User support email**: המייל שלך. **Next**.
3. **Audience**: בוחרים **External**. **Next**.
4. **Contact information**: המייל שלך. **Next**, מסמנים הסכמה ולוחצים **Create**.
5. בתפריט הצד: **Data Access ← Add or remove scopes**. מסמנים את
   `.../auth/drive.file` (See, edit, create, and delete only the specific Google Drive files you use with this app).
   לוחצים **Update** ואז **Save**.
6. בתפריט הצד: **Audience ← Publish app ← Confirm**. בלי השלב הזה רק "משתמשי בדיקה" יוכלו להתחבר.

ההרשאה `drive.file` נותנת לאתר גישה רק לקבצים שהוא עצמו יצר. זו הרשאה "לא רגישה",
ולכן גוגל לא דורשת תהליך אימות ולא מציגה לגבאי אזהרה של "אפליקציה לא מאומתת".

## 4. מזהה ההתחברות
1. בתפריט הצד: **Clients ← Create client**.
2. **Application type**: `Web application`. **Name**: `Zmanim site`.
3. תחת **Authorized JavaScript origins** לוחצים **Add URI** ומוסיפים שתי כתובות:
   - `https://ymalka82810.github.io`
   - `http://localhost:8080`
4. לוחצים **Create**. מופיע **Client ID** שנגמר ב-`.apps.googleusercontent.com`. מעתיקים אותו.

## 5. הכנסת הערכים לאתר
פותחים את `kiddush/js/config.js` ומדביקים את שני הערכים בין הגרשיים:
```js
googleClientId: '1234567890-abc.apps.googleusercontent.com',
gateUrl: 'https://script.google.com/macros/s/AKfy.../exec'
```
שני הערכים ציבוריים. מותר שיופיעו בקוד ובגיטהאב.

## מה קורה כשגבאי יוצר גיליון
- הגבאי מתחבר עם חשבון הגוגל שלו, והגיליון נוצר בדרייב שלו. הוא הבעלים של הגיליון.
- עם שומר סף: הגיליון משותף רק עם החשבון של שומר הסף, והמתפללים לא מקבלים גישה אליו. בלי שומר סף: הגיליון משותף לעריכה לכל מי שיש לו את הקישור.
- בגיליון יש שתי לשוניות:
  - **קידושים**: שורה לכל שבת וחג בשנה הקרובה, והעמודות: תאריך, תאריך עברי, שבת / חג, שם התורם, לע"נ / לזכות, שם, סיבה, טלפון, הערה.
  - **הגדרות**: שם בית הכנסת, מיקום (ארץ ישראל / חוץ לארץ) וקישור ללוח.
- הגבאי מקבל קישור ללוח (`kiddush/?sheet=<מזהה>`) ושולח אותו למתפללים. הם נרשמים בטופס שבלוח.
- עם שומר סף, השומר כותב רישום רק לשבת שעמודת "שם התורם" שלה ריקה, כך שמתפלל אחד לא יכול למחוק רישום של אחר. שינוי וביטול נעשים על ידי הגבאי בגיליון.
- הלוח לא מציג את מספרי הטלפון. הם נמצאים רק בגיליון.
- כשהשנה מתקרבת לסוף, הגבאי לוחץ בלוח על **הגדרות ← הוספת שנה נוספת לגיליון**.
