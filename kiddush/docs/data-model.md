# מבנה הנתונים

טבלאות ב-Convex (`convex/schema.ts`). כל רשומה שייכת לקהילה (`synagogueId`). `dateKey` הוא תאריך השבת או החג בפורמט `YYYY-MM-DD`.

## `kiddushBookings`
רשומה אחת לכל תאריך תפוס. השרת בודק בתוך אותה טרנזקציה שהתאריך פנוי, ולכן אין רישום כפול.

| שדה | משמעות |
|---|---|
| `status` | `pending` (ממתין לאישור), `approved`, `blocked` |
| `userId` | הנרשם. ברישום ידני או בחסימה: הגבאי שרשם |
| `manual` | `true` ברישום ידני ובחסימה |
| `sponsorName`, `sponsorSuffix` | בעל הקידוש, ואחריו שיחי׳ / שתחי׳ / שיחיו (או ריק) |
| `occasionType`, `occasion`, `occasionSuffix` | סיבת הקידוש: לרגל / לזכות / לרפואת / להצלחת / לעילוי נשמת, השם, ואחריו שיחי׳ / שתחי׳ / שיחיו, או ז״ל / ע״ה בלעילוי נשמת. ברישום ישן בלי סוג: "לרגל" |
| `moreOccasions` | סיבות נוספות (עד 4), כל אחת `{ occasionType?, occasion, occasionSuffix? }`. הסיבה הראשונה נשמרת בשדות למעלה. `occasionLine` מחזיר כל סיבה בשורה משלה (ירידת שורה), והלוח המודפס שומר על זה |
| `phone`, `note` | גלויים רק לנרשם, לגבאי ולרב |
| `blockLabel` | הטקסט שמוצג בתאריך חסום, למשל "קידוש קהילתי" |
| `termsVersion`, `termsAckAt` | גרסת ההנחיות שהנרשם אישר |
| `decidedBy`, `decidedAt` | מי אישר ומתי |
| `cosponsors` | שותפים לקידוש (עד 5), רשימה של `{ userId?, sponsorName, sponsorSuffix, status, respondedAt }`. `status`: `pending` (השותף עוד לא אישר) או `confirmed`. שותף בלי `userId` נרשם ידנית ע״י גבאי ונחשב מאושר |

דחייה או ביטול מוחקים את הרשומה ושולחים התראה.

## שותפים לקידוש
- הנרשם בוחר שותפים מחברי הקהילה (`kiddush:memberChoices`, בלי כתובות מייל), וכל שותף מקבל התראה.
- השותף מאשר או דוחה (`kiddush:respondCosponsor`). דחייה מסירה אותו מהרישום. ביטול אחרי אישור, והמשך לבד אחרי שהנרשם ביטל, עדיין לא נתמכים.
- הגבאי לא יכול לאשר בקשה כל עוד יש שותף שלא אישר (`approve` זורק שגיאה). בקשה כזו גם לא נספרת בתג של הגבאי.
- `sponsorLine` בשאילתה `board` כולל רק שותפים שאישרו, כך: "משפחת לוי וע״י משפחת כהן". ה"ע״י" הראשון מתווסף בלקוח, כמו תמיד, ולכן הלוח, היומן, השבוע והלוח המודפס מציגים את השותפים בלי שינוי.
- שותף שעוד לא אישר מופיע ב-`cosponsors` של השאילתה רק לנרשם, לגבאי, לרב ולשותף עצמו.
- ביטול או דחייה של הרישום שולחים הודעה גם לשותפים.
- גבאי או רב מוסיפים בעלי קידוש לרישום קיים (`kiddush:addSponsors`) ומסירים (`kiddush:removeCosponsor`). שותף בלי חשבון נחשב מאושר מיד, ושותף עם חשבון מקבל בקשה לאשר.

השאילתה `board` מחזירה גם `sponsorLine` ("משפחת לוי שיחיו") ו-`occasionLine` ("לזכות בנם משה שיחי׳"), וזה מה שמוצג בלוח הקידושים ובלוח הזמנים המודפס.

## נוסח ההכרזה (`synagogues`)
`kiddushHeading` (השורה הראשונה, למשל "קידוש והתוועדות לאחר התפילה") ו-`kiddushBy` (לפני שם בעל הקידוש, ברירת מחדל "ע״י"). רק גבאי או רב משנים אותם (`kiddush:saveWording`), ובטופס ההרשמה הם טקסט קבוע. בתבנית של לוח הזמנים המודפס הם זמינים כ-`{כותרת}` ו-`{ע״י}` בנוסח של אזור הקידוש.

## `kiddushTerms`
כל שמירה יוצרת גרסה חדשה. הגרסה הנוכחית היא זו עם `version` הגבוה ביותר. כשגבאי או רב פותחים לוח של קהילה בלי הנחיות, נוצרת גרסה 1 מברירת המחדל שב-`convex/kiddush.ts`.

שדות: `version`, `intro`, `items` (רשימת סעיפים), `note` (מה השתנה), `editedBy`, `editedAt`.

## `notifications`
טבלה משותפת לקידוש ולקופה (`convex/notifications.ts`), עם שדה `type` (`"kiddush"` / `"fund"`).

| שדה | משמעות |
|---|---|
| `type` | `"kiddush"` או `"fund"` |
| `to` | מזהה משתמש, או `"managers"` לכל הגבאים והרבנים (בקידוש בלבד — בקופה תמיד מזהה משתמש) |
| `text` | טקסט מוכן להצגה |
| `readBy` | מי כבר קרא |
| `by`, `dateKey` | קידוש בלבד: מי יצר ולאיזה תאריך |
| `transactionId` | קופה בלבד: החיוב שאליו מתייחסת התזכורת |

התראות קידוש בנות יותר מ-120 יום נמחקות כשגבאי או רב פותחים את חלון ההתראות.

## טלפון
הטלפון האחרון שהמשתמש הזין נשמר ב-`memberships.phone`, וממלא מראש את טופס ההרשמה הבא.
